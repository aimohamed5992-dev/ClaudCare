# تطبيقات ClaudCare (Flutter – متصلة بالـ API)

```
flutter/
├─ claudcare_ui/   حزمة مشتركة: الألوان، السمة (Material 3 بخلفية بيضاء)، الخط Cairo، المكونات
├─ doctor_app/     تطبيق الطبيب
└─ patient_app/    تطبيق المريض
```

## التشغيل
```bash
cd doctor_app   # أو patient_app
flutter pub get
flutter run -d chrome        # أو -d <محاكي iOS>
flutter test && flutter analyze
```

## المكونات المشتركة (`claudcare_ui`)
`CcApp` (عربي RTL) · `ccTheme()` · `CcButton` (4 أنماط + تحميل) · `CcTextField` (إظهار كلمة المرور) ·
`CcCard` · `CcBadge` (النص مع اللون) · `CcAvatar` (حروف احتياطية) · `CcPageDots` · رموز التصميم `CcColors/CcSpace/CcRadius`.

## الصور
تُوضع في `assets/images/` داخل كل تطبيق. البرومبتات في `../prompts/flutter/`.

## الـ Splash والـ Onboarding
`CcSplash` · `CcOnboarding` · `CcWelcome` في `claudcare_ui`؛ كل تطبيق يمرّر صوره ونصوصه. يُحفظ إتمام الـ onboarding في `shared_preferences`.
للتجربة المتكررة: `flutter run -d chrome --dart-define=ALWAYS_ONBOARD=true`

## الدخول (تجريبي)
- **الطبيب:** بريد أو رقم موظف + كلمة مرور ← تحقق بخطوتين OTP ← الرئيسية.
- **المريض:** جوال (05…) أو هوية + كلمة مرور ← الرئيسية؛ أو «إنشاء حساب» ← OTP ← الرئيسية.
- استعادة كلمة المرور: معرّف ← OTP ← كلمة جديدة (مقياس قوة) ← نجاح.
- رمز التحقق التجريبي دائمًا `123456`. كلمة المرور `wrongpw` تُظهر رسالة خطأ الدخول. الجلسة محفوظة محليًا.

## تطبيق الطبيب – الهيكل والمواعيد
تنقل سفلي (الرئيسية · المواعيد · المرضى · الرسائل · حسابي). حالة المواعيد مشتركة (`AppointmentsController`) فتتحدّث الرئيسية فورًا
عند التأكيد/الإلغاء/إعادة الجدولة/بدء الكشف. الوقت الحالي المحاكى في البيانات التجريبية: 09:15.

## تطبيق الطبيب – المرضى والكشف
- **المرضى:** بحث (اسم/مرض/جوال) وتصفية (مزمنة، أطفال، كبار السن، حساسية).
- **الملف الطبي:** نظرة عامة · الزيارات · النتائج (مع علم طبيعي/مرتفع/حرج) · الوصفات، وتنبيه الحساسية أعلى الصفحة.
- **الكشف (3 خطوات):** المعاينة والعلامات الحيوية ← التشخيص وطلب الفحوصات ← الوصفة والمتابعة. التحقق من القيم غير المعقولة،
  وتحذير تعارض الحساسية (يمنع الإضافة إلا بإقرار) وتكرار الدواء، وتأكيد عند الخروج بعد إدخال بيانات.
  عند الحفظ تُضاف الزيارة والوصفة لملف المريض ويصبح الموعد «منتهي».

## تطبيق الطبيب – الرسائل والإشعارات والحساب
- **الرسائل:** قائمة محادثات (بحث، عدّاد غير مقروء على التبويب) وشاشة محادثة (إرسال، «يكتب الآن…» ورد تجريبي، رابط لملف المريض).
- **الإشعارات:** من جرس الرئيسية؛ تصفية غير المقروءة، قراءة الكل، سحب للحذف مع تراجع، والنقر ينقل للمريض/المحادثة/المواعيد.
- **حسابي:** الملف الشخصي (تحقق وحفظ ينعكس فورًا) · أوقات العمل (تفعيل الأيام وتعديل الدوام) · الإعدادات (إشعارات وأمان وتغيير كلمة المرور) · المساعدة · تسجيل الخروج بتأكيد.
- كل حالة التطبيق في `DoctorStore` (`state/app_scope.dart`).

## تطبيق المريض – الهيكل والاكتشاف
تنقل سفلي (الرئيسية · الأطباء · مواعيدي · سجلي · حسابي). حالة التطبيق في `PatientStore`.
- **الرئيسية:** تحية وبحث وبانرات (سحب) وتخصصات (النقر يفتح الأطباء مُصفّى) وموعدك القادم واختصارات وأطباء مميزون.
- **الأطباء:** بحث بالاسم/التخصص، تصفية بالتخصص، المفضلة، ترتيب (التقييم/السعر/الخبرة)، وحالة فارغة.
- **ملف الطبيب:** نبذة، أسعار الكشف والاستشارة عن بُعد، أوقات الدوام، اللغات، التقييمات، مفضلة، وزر «احجز موعدًا» (يُربط في الخطوة 9).

## تطبيق المريض – الحجز والمواعيد والسجل الطبي
- **الحجز (3 خطوات):** نوع الزيارة (عيادة/عن بُعد) واليوم والوقت ← لمن الموعد وسبب الزيارة ← مراجعة ودفع. الخانات تستبعد الماضي
  وما حجزه غيرك وما يتعارض مع مواعيدك، والتأمين يخفض المستحق (تحمّل 20%)، وتنتهي بشاشة نجاح.
- **مواعيدي:** قادمة / سابقة / ملغاة؛ التفاصيل مع إعادة جدولة وإلغاء (سبب إلزامي وتنبيه رسوم قبل أقل من 24 ساعة، مع تراجع)،
  مكالمة الفيديو تُفتح قبل الموعد بـ 10 دقائق، وتقييم الزيارات السابقة.
- **سجلي:** ملخص صحي · التحاليل (تقرير بقيم ومدى طبيعي ومؤشر لكل قيمة) · الأشعة (صورة قابلة للتكبير وتقرير) · الزيارات والوصفات.

## تطبيق المريض – الأدوية والفواتير والرسائل والحساب
- **أدويتي:** جدول جرعات اليوم (تأكيد التناول، فائتة/قادمة) ونسبة الالتزام، تذكير لكل دواء، وطلب إعادة صرف (يبرز للأدوية التي تنتهي خلال 5 أيام).
- **فواتيري:** المستحق، تصفية الحالات، تفاصيل مع حصة التأمين، والدفع بطريقة مختارة.
- **الرسائل والإشعارات:** محادثات مع الأطباء والدعم (ردّ تجريبي)، ومركز إشعارات بتوجيه حسب النوع (موعد/نتيجة/دواء/فاتورة).
- **حسابي:** الملف الشخصي · التأمين الصحي (بطاقة والحد السنوي) · أفراد العائلة (يظهرون في الحجز) · الإعدادات وتغيير كلمة المرور · المساعدة · تسجيل الخروج.

## الاتصال بالخادم (الخطوة 9)
التطبيقان يتصلان بالـ API الحقيقي عند التشغيل (`main()`)؛ والاختبارات تبقى على البيانات التجريبية دون شبكة.

| | |
|---|---|
| تشغيل الخادم | `cd backend/src/ClaudCare.Api && dotnet run` ثم XAMPP/MySQL شغّال |
| عنوان الـ API | افتراضيًا `http://localhost:5080` (محاكي iOS) و`http://10.0.2.2:5080` (أندرويد). جهاز حقيقي: `--dart-define=API_URL=http://<IP-الجهاز-المضيف>:5080` |
| حسابات الدخول | المريض `0551234500` · الطبيب `DR-1042` (يتبعه رمز `123456`) · كلمة المرور `Demo@1234` |

**الهيكل:** `claudcare_ui/lib/src/api/` عميل HTTP مشترك (`ApiClient`: Bearer، تجديد الرمز تلقائيًا عند 401 دون تكرار متزامن، أخطاء موحدة `ApiException`)
و`AuthApi` (دخول/OTP/تسجيل/استعادة/خروج) و`PrefsTokenStore` (حفظ الجلسة). في كل تطبيق `data/remote.dart` (`PatientRemote` / `DoctorRemote`) يحمّل البيانات إلى الـ controllers
نفسها فلا تتغير الشاشات؛ التعديلات الصغيرة (قراءة إشعار، جرعة، إعدادات…) متفائلة ثم تُرسل وتُعاد القراءة عند فشلها مع رسالة SnackBar؛
والحجز والسداد وحفظ الكشف تنتظر رد الخادم وتعرض سبب الرفض (خانة محجوزة، تعارض حساسية…). انتهاء الجلسة يعيد لشاشة الدخول.

**تكامل حي:** `flutter test test/live_api_test.dart --dart-define=LIVE_API=http://localhost:5080` في كل تطبيق (يُتخطى افتراضيًا؛ يتطلب الـ API شغّالًا. الطبيب يمر برمز OTP مقيّد بـ30 ثانية بين محاولتين).

**ما بقي بالمحاكاة:** تغيير رقم الجوال، رفع الصور الشخصية، مكالمات الفيديو، الدفع الفعلي (يُسجَّل كدفعة محاكاة)، التحديث اللحظي (يُحدَّث عند تبديل التبويب فقط).
